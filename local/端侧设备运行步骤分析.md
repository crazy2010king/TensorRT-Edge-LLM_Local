# 端侧设备运行步骤分析（适配torch 2.4.0版本限制）

## 前提说明
- **x86环境**：无torch版本限制，可安装最新版本AngelSlim/TensorRT-Edge-LLM，算力强，适合计算密集型任务
- **远端端侧设备（Jetson）**：torch版本固定为2.4.0，ARM架构，算力有限，仅支持适配JetPack版本的软件栈
- **核心原则**：尽量将计算密集、版本要求高的步骤放到x86执行，端侧仅执行和硬件强绑定、必须在目标设备运行的步骤，避开torch版本限制

---

## 四步流水线运行环境分析

| 步骤 | 可在x86运行 | 必须在端侧运行 | 原因说明 | 最佳实践 |
|------|------------|----------------|----------|----------|
| ### 1. 量化压缩（AngelSlim阶段）<br>（FP8/INT4量化、Eagle3训练、词表缩减、SmoothQuant等） | ✅ 完全支持 | ❌ 不建议（受torch版本限制） | 1. AngelSlim的所有量化算法（PTQ、GPTQ、AWQ、LeptoQuant等）均为PyTorch实现，和硬件架构无关<br>2. Eagle3模型训练、词表缩减等计算密集型任务在x86大算力GPU上效率高10倍以上<br>3. 若AngelSlim要求torch版本>2.4.0，端侧完全无法运行 | ✅ **全部放在x86执行**，完成后将量化好的模型权重传到端侧即可 |
| ### 2. ONNX导出（TensorRT-Edge-LLM导出阶段）<br>（LLM/视觉编码器/草稿模型ONNX导出） | ✅ 完全支持 | ⚠️ 可运行但不推荐 | 1. ONNX导出仅需加载PyTorch模型并转成ONNX格式，和硬件架构无关<br>2. 只要x86环境导出的ONNX opset版本适配端侧TensorRT版本，即可无缝使用<br>3. 端侧torch 2.4.0若满足导出工具的版本要求也可运行，但效率低 | ✅ **优先放在x86执行**，导出完成后将ONNX文件传到端侧 |
| ### 3. TensorRT引擎编译 | ⚠️ 可交叉编译但复杂 | ✅ **推荐在端侧运行** | 1. TensorRT引擎是和目标GPU架构强绑定的，Jetson AGX Orin为SM87架构，必须针对该架构编译<br>2. 端侧的TensorRT版本和JetPack版本严格绑定，直接在端侧编译可100%保证兼容性<br>3. x86交叉编译需要配置和端侧完全一致的TensorRT/CUDA版本，配置复杂易出错 | ✅ **优先在端侧执行**：将x86导出的ONNX传到端侧，直接用端侧本地的TensorRT + torch2trt 0.5.0编译引擎 |
| ### 4. 推理部署运行<br>（业务推理、性能测试、精度验证） | ❌ 无意义 | ✅ **必须在端侧运行** | 1. 推理运行需要实际调用端侧硬件加速能力<br>2. 性能、延迟、显存占用等指标必须在真实目标设备上测试才有意义<br>3. 业务部署需要对接端侧外设（摄像头、传感器、车载总线等） | ✅ **只能在端侧执行** |

## 最佳工作流（完美避开端侧torch版本限制）
```
┌─────────────────────────────────┐           ┌─────────────────────────────────┐
│           x86环境                │           │        远端端侧设备（Jetson）    │
│ （无torch版本限制，算力强）       │           │  （torch=2.4.0，仅部署运行）      │
│                                 │           │                                 │
│ 1. 加载原始HuggingFace模型       │           │                                 │
│ 2. 运行AngelSlim量化压缩         │──────┐    │                                 │
│ 3. 训练Eagle3草稿模型（可选）    │      │    │                                 │
│ 4. 导出ONNX模型（LLM+视觉+草稿） │      │    │                                 │
└─────────────────────────────────┘      │    └─────────────────────────────────┘
                                         │
                                         └───▶ 传输量化后权重和ONNX文件
                                         │
┌─────────────────────────────────┐      │    ┌─────────────────────────────────┐
│        远端端侧设备（Jetson）    │◀─────┘    │        远端端侧设备（Jetson）    │
│                                 │           │                                 │
│ 5. 本地编译TensorRT引擎         │──────▶    │ 6. 部署运行推理+业务对接         │
│ （用本地torch2trt 0.5.0）       │           │ 7. 性能/精度验证                 │
└─────────────────────────────────┘           └─────────────────────────────────┘
```

## 版本兼容性注意事项
1. **x86侧注意**：
   - 导出ONNX时选择适配端侧TensorRT版本的opset（通常opset 17-19兼容性最好）
   - 量化时避免使用仅支持最新GPU架构的特性（如Hopper的WMMA等），确保生成的权重兼容Jetson的Ampere/Ada架构
   - Eagle3训练完成后导出为标准PyTorch权重格式，不需要保留训练依赖

2. **端侧侧注意**：
   - 编译TensorRT引擎时指定正确的SM架构：`-gencode=arch=compute_87,code=sm_87`（对应Orin系列）
   - 无需在端侧安装AngelSlim，也不需要升级torch版本，完全避开版本限制
   - 仅需安装TensorRT-Edge-LLM的C++运行时依赖即可，Python依赖仅在编译引擎阶段需要

## 极端情况适配（必须在端侧做量化的场景）
如果因数据安全等原因无法将模型传到x86，必须在端侧做量化：
1. 检查AngelSlim是否兼容torch 2.4.0，若不兼容则降级AngelSlim版本到支持torch 2.4.0的版本
2. 仅执行PTQ量化（训练类任务如Eagle3训练不要在端侧执行，效率极低）
3. 限制校准数据集大小（≤128条），避免端侧内存不足
